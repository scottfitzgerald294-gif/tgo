# 阶段9—18用户材料与启动门禁

## 当前结论

阶段8安全标签为`phase-08-complete`。本次无人值守授权到此结束，
`safe_to_start_phase_09=false`。本文只列准备条件，不实现阶段9—18的真实
RAG、模型、拼多多接口、店铺授权、自动回复、云部署或真实数据导入。

进入任何后续阶段前都必须同时满足：

1. 用户对该阶段给出单独、明确的书面批准；
2. 所有资料有所有者、来源、版本、生效时间和审核人；
3. 真实密钥只配置在批准的密钥管理位置，不进入Git、聊天、日志或截图；
4. 先使用测试店铺、最小权限账号、合成或脱敏数据；
5. 当前阶段测试、静态检查、安全扫描、回滚演练全部通过；
6. 不跨阶段自动开启真实回复或生产流量。

## 阶段9：真实业务资料治理

目标是把真实资料转换成可审核、可版本化的输入合同，不连接模型或拼多多。

用户必须提供：

- 真实商品清单、SKU与参数，包含资料所有者、来源、版本和适用店铺；
- 真实物流政策，包含承运商、地区、时效口径、例外和生效日期；
- 真实售后政策，包含退换、退款、质量问题和升级人工边界；
- 禁止承诺清单，明确不能保证的退款、赔偿、时效、安全和效果表述；
- 每类资料的业务审核人、法务/合规审核人和更新责任人；
- 允许用于测试的脱敏问答样本，以及明确禁止进入系统的个人信息字段；
- 阶段9数据导入与回滚审批。

完成门禁：资料来源可追溯、冲突已由人工裁决、过期策略明确、真实数据保留期限
获批。未满足时不得导入阶段7目录的生产副本。

## 阶段10：TGO知识库与RAG受控接入

目标是通过TGO现有API建立测试知识库，不直接访问TGO数据库。

用户必须提供：

- 阶段9已审核的商品、物流、售后和禁止承诺资料；
- TGO测试租户、测试Collection和最小权限知识管理员账号；
- TGO当前版本的官方知识导入、检索和权限API文档；
- 文档切分、召回范围、店铺/商品/SKU隔离和引用展示规则；
- 允许上传的文件类型、大小、保留期限和删除审批流程；
- RAG验收集、最低召回指标、冲突/无答案时转人工阈值；
- 禁止跨店查询和越权检索的安全验收方案。

完成门禁：测试Collection权限隔离、引用可追踪、过期和未审核知识不可回答，
回滚不删除审计历史。

## 阶段11：模型提供商与回答评测

目标是在隔离测试环境选择模型并评估候选回答，仍不向真实买家发送。

用户必须提供：

- 模型提供商选择、具体模型ID、服务区域和数据处理条款；
- 模型调用预算、速率上限、超时、重试和停机策略审批；
- API Key的批准配置位置，例如测试环境密钥管理器中的命名引用；
- 禁止把Key写入`.env.example`、Git、日志、提示词或测试fixture的确认；
- 脱敏评测集、正确答案、禁止承诺、风险样本和人工评分标准；
- 提示词、系统规则和模型版本变更的审核人；
- 模型故障、低置信、无引用和风险命中时默认转人工规则。

完成门禁：离线评测和安全红队通过，成本上限生效，日志不含Key或真实买家正文，
没有开启真实自动回复。

## 阶段12：拼多多官方API合同确认

目标是只根据官方、当前、可授权的合同编写契约测试，不猜测私有协议。

用户必须提供：

- 拼多多官方API文档的合法来源、版本、发布日期和适用产品；
- 官方消息接收、发送、鉴权、签名、加密、重放和错误处理说明；
- 官方频率限制、重试、幂等、消息顺序和数据保留要求；
- 可用于开发的官方测试店铺、沙箱或联调环境；
- 店铺所有者对测试授权范围的书面确认；
- Webhook回调域名、证书要求和允许的网络来源；
- 官方支持渠道，用于澄清文档歧义。

完成门禁：所有字段和行为都能引用官方合同；无法确认的字段不实现，真实凭据不
进入仓库。

## 阶段13：PDD Connector测试店铺接入

目标是在测试店铺实现受控入站、出站和签名验证，不接生产店铺。

用户必须提供：

- 阶段12通过的官方合同和契约测试；
- 测试店铺ID、最小权限应用授权和可撤销测试凭据；
- 凭据在密钥管理器中的配置位置和轮换负责人；
- 测试回调域名、TLS证书、DNS控制和网络白名单；
- 测试消息时间窗、速率上限、允许买家账号和清理/保留策略；
- 联调联系人、测试时段、失败停止条件和授权撤销步骤。

完成门禁：签名、重放、去重、乱序、限流、失败重试和撤销授权测试通过；仍不接
真实买家或生产店铺。

## 阶段14：TGO会话与人工队列集成

目标是用TGO现有API替换扩展内测试会话和队列，不修改TGO数据库。

用户必须提供：

- TGO测试租户、Agent、Staff、Visitor和Waiting Queue配置；
- TGO当前版本的会话、消息、人工接管和权限API文档；
- 测试API Key或服务身份在密钥管理器中的配置位置；
- PDD店铺/买家/会话到TGO实体的映射和删除/合并规则；
- AI与人工回复所有权、超时、关闭和恢复的业务审批；
- 跨店权限、客服可见范围和审计查询权限矩阵；
- TGO升级兼容和回滚验收方案。

完成门禁：跨店隔离、消息顺序、人工优先、重启恢复和最小核心改动验证通过。

## 阶段15：浏览器客服工作台

目标是让客服在统一浏览器工作台领取、回复、恢复AI和关闭会话，不在每台电脑
运行本地AI。

用户必须提供：

- 客服账号、主管账号、角色权限和店铺分组；
- 排班、队列优先级、SLA、转派、超时和升级规则；
- 人工领取、回复、恢复AI、关闭和误操作撤销SOP；
- 客服可查看的买家字段清单和必须遮蔽的个人信息；
- 浏览器、终端分辨率和公司网络兼容范围；
- 培训负责人、验收客服和可用性验收脚本。

完成门禁：账号最小权限、人工/AI互斥、敏感字段遮蔽、操作审计和浏览器人工
验收全部通过。

## 阶段16：安全、隐私与韧性验收

目标是在上线前验证威胁模型、数据保护、容量和灾难恢复。

用户必须提供：

- 安全负责人、隐私负责人、法务/合规负责人和事件联系人；
- 数据分类、保留、脱敏、导出、删除和访问审计政策；
- Webhook密钥轮换、模型/PDD/TGO凭据轮换和吊销流程；
- 允许的日志字段、日志保留位置和告警接收人；
- 渗透测试范围、依赖漏洞处置时限和上线阻断级别；
- 目标并发、峰值消息量、延迟、可用性和恢复时间指标；
- 数据库备份、恢复演练、死信处置和人工降级SOP。

完成门禁：提示词注入、越权、重放、伪造Webhook、密钥泄露、日志泄露、双重
回复、模型编造和恶意输入测试通过，备份恢复演练有审批记录。

## 阶段17：云环境、域名与可观测性

目标是准备非生产预发布环境，生产发布仍需阶段18审批。

用户必须提供：

- 云服务商、账号、区域、网络、服务器规格和费用审批；
- 预发布与生产环境隔离方案；
- 域名、DNS控制、TLS证书、证书续期责任人；
- 容器镜像仓库、制品签名和部署身份；
- 托管数据库、缓存、对象存储、备份和加密策略；
- 指标、日志、追踪、告警、值班和状态页方案；
- 部署窗口、变更审批、回滚版本和恢复负责人。

完成门禁：基础设施评审、最小权限、加密、备份、监控、容量和预发布回滚演练
通过；不接生产PDD流量。

## 阶段18：试点上线与正式审批

目标是在明确的试点范围内受控上线，并保留即时人工降级和回滚能力。

用户必须提供：

- 正式上线审批人和书面批准；
- 试点店铺、客服账号、商品范围、流量比例和时间窗口；
- 允许使用的真实商品、物流、售后资料最终版本；
- 自动回复允许范围、风险禁区和默认转人工规则最终签字；
- KPI、质量阈值、投诉阈值、成本上限和停止条件；
- 现场客服、技术、业务、安全和拼多多联调联系人；
- 一键停止自动回复、撤销店铺授权和回滚到安全标签的演练记录；
- 试点复盘、扩大范围和终止试点的审批流程。

完成门禁：只有正式批准后才能启用试点流量。任何安全、质量、投诉、成本或权限
阈值触发时立即停止自动回复并转人工，不自动扩大店铺或流量。
